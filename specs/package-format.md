# Package format (.mpkg) — v1

A mini-app ships as a single `.mpkg` file: a ZIP archive with a fixed layout,
integrity metadata, and a build-time Content-Security-Policy. Host-framework
independent. Produced by `mini pack`, validated by `mini inspect` and by every
host before serving a single byte of it.

## 1. Container rules

- Standard ZIP (deflate or stored). UTF-8 entry names.
- Entry names MUST be package-relative: no leading `/`, no `..` segments, no
  backslashes, no symlinks, no duplicate names. Extractors MUST reject
  violations (path-traversal defense — see specs/webview-serving.md).
- Recommended size ≤ 10 MB uncompressed; registries and hosts MAY enforce
  their own limits (`HOST_ERROR` / refusal, not silent truncation).
- `mini pack` SHOULD produce deterministic archives (sorted entries, fixed
  timestamps) so identical inputs give identical package hashes.

## 2. Layout

```txt
todo-0.1.0.mpkg
├── manifest.json      # required — see manifest.md
├── index.html         # required — entry document (or manifest.entry)
├── hashes.json        # required — integrity metadata, generated by pack
├── bundle.js          # app code (name not fixed; referenced by entry doc)
└── assets/            # anything else: images, fonts, css, chunks
```

The only reserved names are `manifest.json` and `hashes.json` at the root.
Everything else is app-defined and referenced relatively from the entry
document.

## 3. Integrity: hashes.json and the package hash

```json
{
  "algorithm": "sha256",
  "runtimeVersion": "0.1.0",
  "files": {
    "manifest.json": "9f2b…",
    "index.html": "ab01…",
    "bundle.js": "77c3…"
  }
}
```

- `files` maps every entry in the archive **except `hashes.json` itself** to
  its lowercase-hex SHA-256.
- `runtimeVersion` records the exact `@openmini/runtime` version bundled at
  pack time (input to the host's compatibility check, `manifest.md` §3).
- The **package hash** is the SHA-256 of the `.mpkg` bytes. It lives OUTSIDE
  the package (registry index, `mini publish` output) and is what hosts verify
  after download, before extraction. `hashes.json` then lets a host audit
  individual files after extraction (cache tamper check).
- Verification order in hosts: download → package hash check → safe extract
  (§1 rules) → per-file hash check → serve. Any failure discards the download
  and leaves the cache untouched.

## 4. Build-time CSP injection

At pack time the CLI injects a `<meta http-equiv="Content-Security-Policy">`
tag into the entry document (replacing any authored one, with a warning).
Baseline template, with `{connect}` = space-separated `allowedDomains`:

```txt
default-src 'none';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
font-src 'self';
media-src 'self';
connect-src 'self' {connect};
```

- `'self'` resolves to the serving origin (the host's custom scheme, or the
  dev server) — package-internal assets keep working without enumeration.
- Empty `allowedDomains` → `connect-src 'self'` — packaged assets stay fetchable via relative URLs; only external origins need declaring.
- This is the enforcement half of `allowedDomains` for raw `fetch()`/XHR;
  the bridge-side check (`manifest.md` §2) covers `network.request`. Both are
  claimed in SECURITY.md only as the pair.
- The exact directive set may be tuned by the CLI build (wasm, websockets — see
  ROADMAP §10 risks); tuning is a spec change to this section first.

## 5. Naming

`mini pack` names the artifact `<last-id-segment>-<version>.mpkg` (e.g.
`todo-0.1.0.mpkg`). The name is cosmetic; identity is `manifest.id` +
`manifest.version`, and integrity is the package hash.
